# Maatify Email Delivery 1.2.0 — release notes

Published on 2026-11-06 UTC. See the [actual Release](https://github.com/Maatify/email-delivery/releases/tag/v1.2.0)
and [publication evidence](1.2.0-publication.md).

## Overview

This additive minor release introduces durable keyed enqueue and isolated synthetic no-send recording,
while retaining legacy per-call enqueue and PHP ^8.2 compatibility. PHP 8.2/8.3/8.4/8.5 are covered by CI.

## Added

- Explicit namespace/key atomic acceptance with content-conflict detection, encrypted canonical digest,
  immutable job/receipt binding and scoped lookup. Durable receipts survive queue deletion and ID reuse.
- Optional encrypted synthetic recording in an independent table/domain, with consumer-selected retention
  and bounded trusted cleanup. No synthetic record enters the mail worker.
- Complete consumer Package Reference, Usage Guide, public-API examples and distribution verification.

## Fixed

Receipt-bound worker due/retry decisions and sent timestamps use database UTC even when worker/PHP
sessions are local. Legacy NULL-token/pre-binding rows retain their previous clock behavior.

## Compatibility and upgrade

Existing `enqueue(): void` keeps one insertion per call. Apply the documented fresh or existing-schema
path before keyed adoption; do not run every numbered SQL file indiscriminately. Upgrade every worker
before enabling keyed callers, configure a dedicated idle UTC/autocommit/exception connection, and
retain real receipts/fingerprint read keys indefinitely. Synthetic schema 004 is independent and optional.

Queue acceptance is not exactly-once SMTP or mailbox delivery. Automatic interrupted-processing recovery
and HTTP/timing-equivalence guarantees are not added. Applications own SMTP policy, authorization,
supervision and synthetic cleanup scheduling. See [schema upgrade](../upgrade.md),
[keyed contract](../reference/idempotency.md) and [synthetic contract](../reference/synthetic-recording.md).
