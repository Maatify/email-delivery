# 1.2.0 preparation semantic review

This records the implementing lead's presentation review for issue #7. It is not an independent
review, owner release approval, completed main-SHA qualification or post-publication result.
Read actual workflow evidence for those later states; this preparation record does not predict them.

| Claim reviewed | Source/evidence and boundary |
| --- | --- |
| Target is 1.2.0, not the previous published artifact | release-target.json, VERSION, README exact artifact/install target; installed availability is explicitly conditional on publication |
| Existing Stable support is preserved | SECURITY keeps 1.x support and private security@maatify.dev; prepared target creates no new support line |
| Represented changes allocated to 1.2.0 | Undated 1.2.0 CHANGELOG section; empty Unreleased; no invented target date/release link |
| Public contract is complete and consumer-focused | Package Reference lists own public constructors/methods/properties/enums; constituent keyed/synthetic chapters remain authoritative in scope; Internal helpers excluded |
| Legacy and keyed behavior differ intentionally | Source/unchanged runtime tests: per-call legacy insert versus keyed atomic acceptance; neither proves exactly-once SMTP |
| Synthetic data remains inert | Independent table/crypto domains, explicit retention and bounded trusted cleanup; no worker handoff or timing-equivalence claim |
| Renderer/transport/worker limits are explicit | Subject+HTML only, TLS policy belongs to the caller, claim commits before transport, no automatic processing recovery |
| Canonical examples remain discoverable | Root examples use public API/production autoload; old docs paths are compatibility includes; host prerequisites and safe smoke boundary are explicit |
| Distribution is checked, not inferred from Git cleanliness | Actual Composer/Git export comparison; IDE/environment/dev paths rejected; all consumer docs/source/schema retained; isolated archive production autoload |
| External publication remains separate | PAV command/workflow require exact external version, observed dist, qualified references and all installed bytes; source fallback fails; live freshness is independent |

The presentation baseline is [std-library-presentation 5.0.1](https://github.com/Maatify/php-engineering-standards/blob/698b0735c58ee388d650542336989b90e06d7003/standards/packages/LIBRARY_PRESENTATION_STANDARD.md),
with its referenced CI release-evidence boundary. This is scoped readiness work, not a claim of blanket
adoption of unrelated engineering standards. Runtime source/dependency constraints and license are unchanged.
Maintainer review should assess these semantic claims alongside actual archive/CI evidence before tag approval.
